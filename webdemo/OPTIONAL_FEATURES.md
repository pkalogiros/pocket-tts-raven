# Optional browser features

The C++ engine, compiled to WASM, now exposes the same steering mechanism as the
native CLI. Both fixed-memory and growth-memory bundles are rebuilt. The web UI enables steering with the Default (Varkos) vectors on startup.
Use `?soura=0` or uncheck Emotion steering to select the original graph.
The experimental split engine does not support steering. Direct worker and native
CLI defaults remain opt-in.

## Page controls

**Emotion & vector controls** are collapsed by default below the text field; click the heading to expand them. VARKOS is the default voice, using the companion’s Dramatic neutral reference embedding; ALBA remains selectable. Voice identity and emotion steering are independent.

Controls:

- **Emotion steering** enables the steering graph and reloads the engine.
- **Emotion / Intensity** apply to the next generation; neutral or zero intensity
  bypasses the shift. Intensity is finite, between 0 and 1.2.
- **Seed** is optional; blank chooses a new random seed. Use integers from 0 to
  9007199254740991. The native and JS engines use different RNG algorithms;
  the same number is not a cross-engine waveform-matching guarantee.
- **Vector set** shows **Default**, the Varkos reference-derived vectors from
  `models/soura_vectors.derived.npy`. This is the demo’s only bundled selection;
  it is used whenever steering is enabled, including without a `vectors` URL flag.
- **Custom vectors** loads a `[6,1024]`, little-endian, C-order float32 `.npy` file
  for the session. Invalid files are rejected without replacing active vectors.
  The upload is local and is never sent to the server.
- **Prepare voice caches separately** enables disposable KV preparation and
  persistent clone caches. This requires the native WASM engine and reloads it.

Shareable equivalent flags:

```text
/                         # Varkos + steering; no query parameters needed
?soura=0                  # steering off
?prepareCaches=1&variant=growth
```

Omit each flag, or set it to `0`, to keep its old behavior. `?keepCommas=0` opts
out of the browser's existing punctuation preservation. `?engine=native` selects
the default C++/WASM engine; `?engine=ts` selects the JS/onnxruntime-web engine.

| Feature | Native WASM | JS/ONNX engine | Experimental split engine |
|---|---|---|---|
| Emotion / intensity | Yes | Yes | Explicitly unsupported |
| Custom vector files | Yes | Yes | Unsupported |
| Seed | Yes | Yes, different RNG | No new seed control |
| Disposable KV preparation / cache persistence | Optional | Existing in-memory snapshots | Unsupported |
| Reference-derived vector inference | Yes | Yes | Unsupported |

Reference **derivation** remains the offline Python tool in `tools/`; this change
makes its output usable in-browser. It does not run activation extraction or
training in the browser. The web demo ships a Varkos voice embedding and derived vectors, but no
reference recordings or character playback DSP.

## Prepare assets and rebuild

From the repository root:

```sh
# Use the compressed ONNX assets shipped in Git; verifies both sets of hashes.
uv run --no-project --with brotli python webdemo/unpack_models.py
# To regenerate from upstream instead: ./tools/prepare_models.sh --web

# Only needed when changing C++/WASM code; the built runtimes ship in Git.
ORT_WASM_ROOT=/path/to/ort-wasm ./webdemo/wasm/build.sh
uv run --no-project --with brotli python webdemo/compress.py
uv run --no-project --with brotli python webdemo/check_assets.py
python3 webdemo/serve.py
```

The build supports `EM_CACHE=/writable/cache` and `PTT_BUILD_JOBS=N`. Steering
preparation preserves the original graphs so the off switch still works.
Both engine variants are generated by the standard command. The small Default
vectors, provenance JSON and Varkos embedding ship in Git, alongside the seven
compressed ONNX files. Raw ONNX files and other `.br` sidecars are generated
locally. The ONNX hash manifest must be updated when replacing bundled models.

Before deploying, run the asset check and browser tests, then publish the web
files **including generated models** and the matching `.mjs`/`.wasm` pairs.
Exclude `.certs/` (local private keys), build directories and test fixtures.
The host must serve COOP `same-origin`, COEP `require-corp`, and WASM as
`application/wasm`. When serving `.br` sidecars, use `Content-Encoding: br` and
publish them together with their originals. `check_assets.py` rejects missing
runtime/model assets, a mismatched Default vector hash, and stale `.br` files.
The check also accepts `--root /path/to/staged/webdemo` for a deployment staging
folder. It does not publish anything or verify a remote host's headers.

The new graph uses an ordinary Add operation and retains each engine's existing
attention and decoder choices. Apple-specific decoder kernels are not needed.

## Worker protocol and C API

```js
worker.postMessage({type: 'init', modelsUrl: '/models', soura: true,
  vectorsUrl: '/models/soura_vectors.npy', prepareCaches: false});
worker.postMessage({type: 'speak', text: 'Hello there.', voiceKey: 'alba',
  emotion: 'happy', intensity: 0.8, seed: 31});
// An ArrayBuffer containing a validated NPY vector set:
worker.postMessage({type: 'loadVectors', buffer}, [buffer]);
```

The native worker serializes synthesis and vector changes. Every synthesis resets
emotion to neutral if omitted; prewarming cannot retain the last spoken emotion.
`ready` reports `soura`, `samplingSeed`, and `prepareCaches`. A successful upload
emits `vectorsLoaded`. Native and JS worker requests accept an optional `id` and
emit `ack` after completion; errors identify the failed request type.

The new C exports are `ptt_set_emotion`, `ptt_set_seed`,
`ptt_load_soura_vectors`, and `ptt_prepare_voice`, returning 0 on success and -1
on failure. Creation flag bit 3 enables steering; bit 4 creates a conditioning-only
engine for cache preparation. Existing flag values remain compatible. See
`include/pocket_tts.h` for lifetimes, allowed combinations, and caller obligations.

Steering-enabled native workers mount the selected sibling graph with a virtual
symlink for normal graph discovery. They do not download or hold both AR graphs.

## Cache lifetime

The encoder already runs in a disposable worker. With `prepareCaches` enabled,
a second disposable worker loads only AR/text/BOS assets, conditions the cached
embedding, and returns the `.kv` snapshot. Terminating that worker releases its
WASM heap. It generates no throwaway speech and loads no decoder. The persistent
engine restores that snapshot instead of doing a full voice-conditioning pass.

Cloned WAV, embedding, and KV files persist in OPFS. Cache metadata includes the
selected AR graph and BOS hashes; incompatible caches are ignored and rebuilt.
Writes are serialized so a cache update cannot race the initial voice save.
Presets are prepared for the session; clone caches persist across page reloads.
The mobile cloning workflow prepares the embedding and KV snapshot **before**
restarting the main engine. This adds preparation work and a temporary worker;
there is no blanket memory or latency guarantee for every device.

## Checks and numerical limits

```sh
cd webdemo
npm test
npm run test:assets
npm run check:assets  # requires brotli if compressed sidecars are present
# Requires prepared steering models and both vector files:
npm run test:wasm
# Install Playwright and Chromium, or set PLAYWRIGHT_MODULE to an existing install:
npm run test:browser
```

The browser test launches its own localhost server and temporary Chromium
profiles. It exercises disabled startup asset selection, native and JS steering,
custom vectors, cancellation/recovery, plain-URL Varkos startup, collapsed
controls, preset labels, steering off/on reloads, playback, and the mobile clone/cache
restoration path in Chromium mobile emulation. A real iPhone/Safari validation
is still required before claiming device-specific parity.

In the tested WASM builds, zero steering matched the original graph's first
latent frame exactly. Longer original-versus-zero trajectories diverged as tiny
rounding changes fed back through recurrent generation. Tests therefore separately
check first-frame equivalence and exact repeatability/neutral recovery within
the same graph. Native and WASM full waveforms are not expected to match exactly.

## Verified in this port (2026-09-14)

- Both real Emscripten bundles rebuilt against the existing ONNX Runtime 1.27.0 library.
- Fixed and growth Node/WASM tests passed: controls, invalid vectors, fixed-seed repeatability, neutral recovery, all emotion labels, cancellation, and conditioning-only cache transfer.
- Chromium worker tests passed for native/default, native/growth with steering and disposable preparation, and the JS/ONNX engine. Disabled startup fetched no steering assets.
- Page custom-vector loading and playback passed. Chromium mobile emulation passed real sample-voice cloning, OPFS cache persistence, reload/restoration, and playback.
- Existing tokenizer/state-transfer/engine tests and the native CMake regression passed.
- Eight rebuilt/generated WASM, graph, and vector assets were checked against their Brotli sidecars; decompression reproduced the originals exactly.
- Physical iPhone/Safari and Firefox were not tested. No new speed or device-memory benchmark is claimed.
